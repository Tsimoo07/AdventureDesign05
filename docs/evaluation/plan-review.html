밥길 비대면 형성평가 계획

방식: 각자 데모 체험 + 짧은 온라인 설문 · 총 3–5분

목적과 대상

충남대 학생이 식사 공간 탐색·혼잡도 해석·즐겨찾기를 스스로 수행할 수 있는지 확인하고 개선한다. 1차 5–8명을 권장하며 통계적 대표성보다 문제 발견을 목적으로 한다. 실시간 정보의 정확도는 평가하지 않는다.

준비

  1. Vercel에 같은 평가용 빌드를 배포하고 로그인 없이 열리는지 확인한다.
  2. 학생 의견지의 문항을 Google Forms 또는 네이버 폼에 옮긴다. 이메일·실명·학번 수집과 로그인 요구는 끈다. 실제 설정을 별도 브라우저에서 확인한다.
  3. 데모 URL과 실제 설문 URL을 참여 안내에 넣고 담당자·응답 마감일·익명 답변 보관 종료일을 안내한다.
  4. 휴대폰으로 체험 → 설문 제출까지 사전 점검한다. 평가 기간에는 배포 버전을 고정한다.

참여자에게 보낼 안내

밥길을 3분 정도 써보고 짧은 의견을 들려주세요. 여러분의 능력이 아니라 앱을 평가합니다. 막히면 건너뛰어도 됩니다.

데모 링크: [배포 후 입력]
설문 링크: [설문 생성 후 입력]

  1. 식사할 곳을 찾아 1학생회관에서 덜 붐비는 구역을 확인해 주세요.
  2. 2학생회관의 상태도 확인한 뒤 장소 목록으로 돌아와 주세요.
  3. 1학생회관을 저장하고, 저장한 장소만 모아서 찾아주세요.

시간이 되면 시간표에 수업을 하나 추가하거나 메뉴에서 화면 모드를 바꿔보세요. 선택 과제입니다.

혼잡도·버스는 예시이며 실제 정보가 아닙니다. 시간표 가져오기는 가상 수업 체험입니다. 실명이나 개인 링크는 입력하지 마세요. 입력한 앱 데이터는 해당 브라우저에 남습니다. 참여·응답은 선택이며 언제든 중단할 수 있습니다.

응답 방식 — 약 1분

핵심 과제 3개는 ‘완료 / 하다가 막힘 / 안 해봄’으로 표시하고, 기능 찾기와 혼잡도 이해 문항에 답한다. 가장 불편한 화면 1개와 선택적인 한 줄 의견을 받는다. 직접 관찰·녹화·진행자 동석은 필요하지 않다.

분석과 개선

  • 과제별 완료 수 / 시도한 응답자 수를 계산한다. ‘안 해봄’은 분모에서 제외한다. 자기보고 결과이며 실제 관찰 성공률로 표현하지 않는다.
  • 막힘 응답과 불편한 화면·한 줄 의견을 연결해 문제를 분류한다. 왜 막혔는지 불명확하면 추정으로 표시한다.
  • 데이터 손실·예시 정보 오해 → 핵심 과제 막힘 → 반복되는 불편 → 미관 취향 순으로 검토한다. 빈도만으로 결정하지 않는다.
  • 문제 / 응답 근거 / 영향 / 수정안 / 재검증 과제를 기록하고, 핵심 수정 후 소규모로 다시 평가한다.
  • 부가기능 미체험을 실패로 처리하지 않는다. 점수는 자체 문항이며 SUS 등 표준 척도로 해석하지 않는다.

원안과 달라진 점

직접 관찰과 생각 말하기를 비대면 과제·자가보고로 대체했다. 제거된 검색창 관련 항목을 삭제하고, 현재 식사 목록 진입 경로를 반영했다. 시간표·버스·설정은 참여 부담을 줄이기 위해 선택 체험으로 조정했다. 구체적인 클릭 경로와 정답 색상은 미리 알려주지 않는다.

한계: 실제 클릭 순서·소요 시간·막힌 원인은 직접 확인하지 못한다. 따라서 만족도만으로 사용성 문제가 없다고 결론내리지 않는다.
