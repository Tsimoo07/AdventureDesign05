# 밥길 | 형성평가 이후 남은 개발 작업

형성평가는 종료됐다. 다음 작업은 학생들이 실제로 막힌 지점을 고치고, 예시 데이터로 동작하는 기능 중 어디까지 운영할지 결정하는 것이다. 아래 운영 우선순위는 설문 결과가 아니라 현재 구현 상태를 기준으로 한 제안이다.

## 1. 평가 결과에서 수정할 항목 정하기

1. 덜 붐비는 구역 찾기, 학생회관 전환, 저장한 구역 다시 찾기의 완료·막힘 응답을 각각 집계한다. 미시도와 무응답은 따로 두고, 자기보고 결과를 인원수로 표시한다.
2. 막혔다는 응답을 화면과 동작에 연결한다. 원인을 알 수 없는 의견은 추정으로 남긴다. 데이터 손실·예시값 오해·과제 진행 불가를 먼저 검토한다.
3. 재현된 문제마다 ‘응답 근거 → 재현 경로 → 기대 동작’을 기록한다. 수정 후 같은 경로를 휴대폰에서 다시 수행해 완료 여부를 확인한다.

## 2. 실제 서비스로 전환할 때 남은 구현

| 우선순위 | 현재 → 남은 구현 | 운영판 완료 기준 |
|---|---|---|
| P0 · 식사 혼잡도 | 구역별 채색과 API 표시 경로는 있다. 평가판은 예시값을 쓴다. 실제 공급원과 구역 ID를 연결하고 측정 시각을 표시한다. | 한 구역의 새 측정값을 보내면 해당 구역의 색·상태 문구·측정 시각이 함께 바뀐다. 누락·지연·연결 실패는 ‘정보 없음’ 또는 ‘마지막 확인’으로 표시하며 예시값이나 ‘원활’로 대체하지 않는다. |
| P1 · 시간표 가져오기 | 수동 입력, 30분 눈금, 밤 10시 수업, 가져오기 미리보기는 있다. 평가판은 가상 수업을 쓰며 실제 링크 처리는 로컬 서버에서 확인한 상태다. 운영 환경에 가져오기 경로가 필요하다. | 허용된 공유 링크로 배포 환경에서 미리보기가 뜨고, 확인해야 기존 수업이 교체된다. 비공개·만료·차단된 링크와 취소 동작은 기존 시간표를 보존한다. |
| P1 · 버스와 지도 | 현재 도착 정보는 예시다. 지도 표시와 실제 도착 정보 수신은 별도 작업이다. | 지도 키가 없어도 외부 지도 링크를 쓸 수 있다. 공급원이 확보되면 정류장별 도착 정보와 갱신 시각을 표시하고, 수신 실패 시 예상 시간을 지어내지 않는다. |
| P2 · 계정 | 로그인 화면만 있다. 여러 기기에서 저장한 구역이나 시간표를 써야 한다는 수요가 확인될 때 검토한다. | 구현한다면 실제 인증 성공 후에만 로그인 상태를 표시한다. 로그인 취소 시 게스트로 계속할 수 있고 기존 브라우저 데이터가 유지된다. |

**착수 조건:** 혼잡도 공급자와 구역 ID·측정 주기·지연 판정 기준을 먼저 합의한다. 공급원이 없으면 예시 표시를 유지한다. 버스와 시간표도 각각 데이터 이용 조건과 배포 환경의 접근 가능성을 확인한 뒤 연결한다.
